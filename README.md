# Digvation Website

Astro + TypeScript + Tailwind CSS implementation of the Digvation company/marketing website.

## Stack

- Astro 7, static-first
- TypeScript
- Tailwind CSS 4 through `@tailwindcss/vite`
- Astro Content Collections
- Cloudflare Pages static hosting
- Cloudflare Pages Function for `/api/inquiry`
- Cloudflare Turnstile-ready inquiry protection
- GA4 + Google Tag Manager + Microsoft Clarity measurement foundation
- Sitemap, canonical, hreflang, Open Graph and JSON-LD
- Vitest unit tests

The site is intentionally Astro-native. Marketing/content routes are prerendered to HTML. Browser JavaScript is limited to real interaction, motion, analytics, and progressive enhancement. The inquiry backend runs separately as a Cloudflare Pages Function.

## Local development

```bash
cp .env.example .env
npm install
npm run dev
```

`astro dev` previews the static site. To test the real Cloudflare Pages Function locally, copy `.dev.vars.example` to `.dev.vars`, then:

```bash
npm run build
npm run preview:pages
```

## Inquiry configuration

Production should use `resend` or `webhook`. `none` is only for local/static UI testing.

```env
INQUIRY_PROVIDER=resend
INQUIRY_RECIPIENT=hello@digvation.id
INQUIRY_FROM=Digvation <website@digvation.id>
RESEND_API_KEY=...
```

Recommended anti-abuse setup on Cloudflare:

```env
TURNSTILE_MODE=turnstile
TURNSTILE_SECRET_KEY=...
TURNSTILE_ALLOWED_HOSTNAMES=digvation.id,www.digvation.id
PUBLIC_TURNSTILE_SITEKEY=...
```

Turnstile is validated server-side by `/api/inquiry`; the secret never reaches the browser.

## Analytics and future ads

The website deliberately separates analytics from future marketing tags:

```env
PUBLIC_ANALYTICS_MODE=consent
PUBLIC_GA_ID=G-XXXXXXXXXX
PUBLIC_GTM_ID=GTM-XXXXXXX
PUBLIC_CLARITY_ID=xxxxxxxxxx
PUBLIC_WHATSAPP_NUMBER=628xxxxxxxxxx
```

- `PUBLIC_GA_ID` sends Digvation semantic events directly to GA4.
- `PUBLIC_GTM_ID` is the marketing-tag entry point. Add Google Ads, Meta Pixel, or later campaign tags in GTM without another source-code deployment.
- `PUBLIC_CLARITY_ID` enables optional Clarity behavior analysis.
- All optional providers load only after consent when `PUBLIC_ANALYTICS_MODE=consent`.

Important: because GA4 is already sent directly by the website, do **not** create a second GA4 page/event implementation in GTM unless you first disable the direct GA integration. GTM should initially be used for advertising/campaign tags.

Key events already emitted include:

```text
page_view
project_view
case_study_view
service_view
cta_click
contact_start
contact_submit
contact_success
whatsapp_click
email_click
outbound_project_click
```

`contact_success` is emitted only after `/api/inquiry` confirms successful delivery. UTM parameters, `gclid`/`fbclid`, landing page, and referrer are also carried into the lead payload.

See `docs/PRE_DEPLOY_CLOUDFLARE.md` and `docs/MEASUREMENT.md` before the first production deployment.

## SEO

`BaseLayout.astro` owns global canonical/hreflang/OG metadata. Schema helpers live in `src/lib/seo/schema.ts`. Sitemap is generated by `@astrojs/sitemap`; `robots.txt` is generated as an Astro route.

For Google Search Console, prefer a **Domain property verified through Cloudflare DNS**. The HTML verification env remains available only as a fallback.

## Deployment

Cloudflare Pages build configuration:

```text
Build command: npm run build
Build output directory: dist
```

Push the repository to GitHub/GitLab, connect it to Cloudflare Pages, configure Production/Preview variables and secrets, then deploy. Do not use the old Node standalone runtime.
