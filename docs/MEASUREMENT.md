# Digvation Measurement Plan

The website is designed to answer two different questions:

1. **Can people find Digvation?** — Search Console / SEO measurement.
2. **Do visitors understand and trust Digvation enough to continue?** — GA4 event funnel and optional Clarity behavior analysis.

Do not judge the site from total traffic alone. A smaller number of relevant visitors who reach work, contact, and inquiry is more useful than large unqualified traffic.

## Recommended production stack

- **Google Search Console** — organic impressions, clicks, CTR, queries, pages, countries, indexing and Core Web Vitals.
- **Google Analytics 4** — page and conversion/event funnel measurement.
- **Google Tag Manager** — marketing-tag entry point for future Google Ads / Meta Ads measurement without source-code changes.
- **Microsoft Clarity (optional)** — heatmaps and session recordings to understand scrolling, ignored areas, repeated clicks and interaction friction.

All browser measurement is configured through environment variables. Provider IDs are not scattered through components.

## Environment

```env
PUBLIC_ANALYTICS_MODE=consent
PUBLIC_GA_ID=G-XXXXXXXXXX
PUBLIC_GTM_ID=GTM-XXXXXXX
PUBLIC_CLARITY_ID=xxxxxxxxxx
PUBLIC_GOOGLE_SITE_VERIFICATION=xxxxxxxxxx
```

`PUBLIC_ANALYTICS_MODE`:

- `off` — no browser analytics.
- `consent` — recommended default; providers load after visitor opt-in.
- `always` — load immediately. Only use when your privacy/legal basis supports it.

## Search Console setup

The site already provides:

- crawlable HTML
- canonical URLs
- hreflang
- sitemap
- robots.txt
- page-specific titles/descriptions
- structured data
- shareable project URLs

After deployment:

1. Add `https://digvation.id` to Search Console. Domain-property DNS verification is preferred when available; the environment token also supports HTML meta verification.
2. Submit the sitemap URL generated by the production Astro build (commonly `https://digvation.id/sitemap-index.xml`; confirm it after deploy).
3. Check Page Indexing after launch and after major route/content changes.
4. Review Search Performance by **query**, **page**, **country**, and **device**.
5. Inspect Core Web Vitals and fix real-user problems rather than optimizing a score in isolation.

## AI search visibility

If Google Search Console exposes its Generative AI performance report for the property, review impressions and pages appearing in supported generative search experiences alongside normal Search performance. Treat this as an additional visibility signal, not a replacement for ordinary clicks, leads, and useful content quality.

## Event taxonomy

The website emits semantic events instead of provider-specific calls inside random components.

| Event                 | What it tells us                                                      |
| --------------------- | --------------------------------------------------------------------- |
| `page_view`           | Which pages people actually visit                                     |
| `section_viewed`      | Which homepage sections are genuinely reached                         |
| `scroll_depth_50`     | Visitor reached the middle of a long page                             |
| `scroll_depth_90`     | Visitor consumed most of a long page                                  |
| `cta_clicked`         | Which CTA wording/placement creates action                            |
| `portfolio_opened`    | Which project creates curiosity                                       |
| `portfolio_completed` | Whether people consume a case study deeply                            |
| `service_viewed`      | Which solution pages attract attention                                |
| `inquiry_started`     | Visitor began interacting with the inquiry form                       |
| `inquiry_submitted`   | Primary website conversion; mark this as a GA4 key event / conversion |
| `generate_lead`       | Standard lead event emitted after the same successful delivery        |
| `email_clicked`       | Visitor chose direct email instead of the form                        |
| `language_switched`   | Language preference                                                   |
| `outbound_clicked`    | External destinations receiving traffic                               |

## Google Tag Manager and paid-media readiness

GA4 is sent directly from the website through `PUBLIC_GA_ID`. GTM receives the same semantic Digvation events through `dataLayer` and is reserved for campaign tags. This avoids scattering Google Ads or Meta Pixel code throughout Astro components.

Do not duplicate GA4 in GTM while direct GA4 is enabled.

When paid campaigns are enabled:

```text
Digvation event: inquiry_submitted
        ↓
GTM custom-event trigger
        ├─ Google Ads lead conversion
        └─ Meta Pixel Lead
```

For Google Ads, add a Conversion Linker and a conversion tag triggered by `generate_lead` or `inquiry_submitted`—choose one primary trigger, not both. For Meta Ads, map that same successful lead to `Lead`. Test both in provider debugging tools before spending budget.

`inquiry_submitted` is emitted only after the Cloudflare Pages Function confirms successful inquiry delivery. Do not use button clicks as the primary lead conversion.

Campaign attribution is retained for the browser session and submitted with the enquiry: `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `gclid` or `fbclid`, landing page, and referrer. This attribution does not replace provider-side conversion diagnostics, but it makes the source visible in the delivered lead or CRM webhook.

## Primary funnel

Track this as the main business funnel:

```text
Relevant visit
→ understands the first screen
→ reaches problem/work content
→ opens a case study or contact
→ starts inquiry
→ submits inquiry
```

Useful rates:

```text
Hero CTA rate
= hero CTA clicks / homepage sessions

Work interest rate
= portfolio_opened / homepage sessions

Contact intent rate
= contact page views / relevant sessions

Inquiry start rate
= inquiry_started / contact page views

Inquiry completion rate
= inquiry_submitted / inquiry_started

Visitor-to-lead rate
= inquiry_submitted / relevant sessions
```

Do not optimize a single metric blindly. For example, increasing CTA clicks while lowering inquiry quality is not an improvement.

## What to review weekly

### Search demand

- impressions
- clicks
- CTR
- average position as supporting context, not the only goal
- queries that produce impressions but weak CTR
- pages receiving organic traffic
- branded vs non-branded search patterns

### Visitor interest

- most-viewed sections
- CTA clicks by label/location
- projects opened
- case-study completion
- solutions viewed
- contact page visits
- inquiry starts and completions

### Friction

With Clarity enabled, review:

- click heatmaps
- scroll maps
- mobile vs desktop behavior
- repeated/dead clicks
- where users stop before contact
- recordings of sessions that started but did not complete inquiry

Never use recordings to collect sensitive form content intentionally. The inquiry form is explicitly marked with `data-clarity-mask="true"` in addition to Clarity's built-in masking. Keep project-level masking/privacy settings appropriate.

## First optimization questions

After enough real traffic exists, ask:

1. Do visitors understand Digvation from the first screen without scrolling?
2. Which business-problem statement is reached/read most often?
3. Which case study gets opened most?
4. Do visitors move from work to contact?
5. Which fields or moments create friction before inquiry submission?
6. Which search queries bring visitors who later engage deeply?
7. Does mobile behavior differ meaningfully from desktop?

Use those answers to change copy, hierarchy, portfolio order, CTA placement, and content — not personal preference alone.
